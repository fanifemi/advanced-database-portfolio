R1  IDEMPOTENCY FAST-PATH — reject duplicate API requests before they reach PostgreSQL
==========================================================================================
  Key ph:idem:<reference>, value = request status, TTL 24h. SET … NX succeeds only for the first caller.

  > SET ph:idem:PH-API-27ddd1b6 PROCESSING NX EX 86400             -> True
  > SET ph:idem:PH-API-27ddd1b6 PROCESSING NX EX 86400  (retry)    -> None
  > GET ph:idem:PH-API-27ddd1b6                                    -> {"status": "SUCCESSFUL", "txn_id": 123456}
  > TTL ph:idem:PH-API-27ddd1b6                                    -> 86400

  50 concurrent duplicates of PH-API-6d30a009: 1 accepted, 49 rejected as duplicates
  Note: this is only a fast-path. The UNIQUE constraint on transactions.reference (Portfolio 3, E4) remains the
  guarantee, because Redis data can be lost on failover; the database cannot be bypassed for money.
